# 放卷自动识别：录制样本与去重

## 如何录制

1. 刷新学习看板，摄像头下方有「自动识别：开」和检测原因；开启时稳定后自动抓拍并批改。
2. 展开「临时采集 · 已录样本」，可填场景备注，例如“正常放下”“缓慢放下”“翻页”。
3. 点击「录制样本」。建议每段10–20秒，从空桌开始，再放下试卷，保持静止几秒后停止。
4. 可在认为纸张已稳定、应开始识别时点「标记已放稳」。它只记录时间点，不会强制抓拍。
5. 点击「停止录制」。把显示的 `rec_...` 编号发给开发助手即可，文件已在服务器，不需要上传。

录制期间一直显示实时画面，自动识别结果照常进入左侧；录制不采集麦克风，不上传整段视频到云端。
每段最多60秒或250MiB（预留编码缓冲，可能略早停止）；总预算2GiB。空间不足拒绝开始，不自动删样本。
关闭浏览器不会马上丢弃录像，仍受自动停止上限约束。服务正常重启前会保存并结束录像。

推荐分别录：
- 正常放下、快速放下后静止；
- 很慢地放下、略倾斜放下；
- 移走再放回同页；
- 翻到不同页；
- 手部短暂遮挡、轻微晃动、阴影或灯光改变；
- 同一页修改一道答案，再重新放下或手动抓拍。

## 自动抓拍与去重

- 保持宽高比的缩略图做轻量稳帧，结合相对参考画面的累计变化，避免只看相邻帧导致缓慢动作无法解锁。
- 稳定候选再做模板匹配；页码未匹配、纸面明显缺失等会明确显示原因，不伪装识别成功。
- 同一已知页按透视矫正后的答题区图像做保守相似度比较，容忍小配准偏差。高度相似时发 `capture.reused`，复用原捕获ID和题目，不追加左侧题目，也不再次调用模型。
- 答题区内容发生明显变化时允许新批改。原有判题失败时复用旧题目重试，不重复插入。
- 去重范围是内存保留的最近20次有效抓拍；服务重启/会话重置后不跨会话去重。相似度仍需真实样本调优，不承诺所有拍摄角度都已覆盖。
- 目前支持已入库模板，未入库试卷仍会提示无法匹配；这次未增加任意试卷全文OCR或图像拉白。

## 保存内容

`data/capture_recordings/<ID>/`：
- `video.avi`：原分辨率、15FPS采样、MJPEG视频，浏览器可下载，供OpenCV离线读取。
- `frames.jsonl`：每帧实际采集时间、相机序号与采样时间。AVI名义帧率不能替代真实时间。
- `events.jsonl`：初始开关状态、检测指标、抓拍/复用、用户放稳标记。
- `manifest.json`：录制参数、检测参数版本、结束原因、帧数/丢帧统计。

## 离线回放

不打开真实相机、不请求云端API。复用线上状态机、模板匹配和答题区去重函数：

```bash
backend/.venv/bin/python tools/replay_capture.py --recording rec_实际编号
```

默认输出到 `data/capture_replays/replay_.../`，含逐帧决策、抓拍图及 `report.json`。
结果同时区分新抓拍和复用。没有人工标注时只报告事件与耗时，不计算或编造准确率。

需要评估漏触发和延迟时，用标注JSON，例如：

```json
{
  "events": [
    {"ready": 2.0, "until": 4.0, "action": "capture"},
    {"ready": 8.0, "until": 10.0, "action": "reuse"}
  ],
  "invalid": [{"start": 0, "end": 1.5}]
}
```

`ready` 是纸面真正稳定时间，`until` 是该放置事件的容许窗口；标记按钮有人工反应延迟，需回看视频确认。

```bash
backend/.venv/bin/python tools/replay_capture.py --recording rec_实际编号 --annotations data/capture_recordings/rec_实际编号/labels.json
```

初始目标为稳定后约0.5–1秒抓拍，实际目标达成情况以真实视频评估为准。判题解析耗时单独统计。

## 运维

`RECORDING_ENABLED=true` 启用临时入口；默认示例配置为false。关闭后不能新建录制，已有样本保留。
通过 `systemctl --user restart dahetao-study-lamp.service` 重启，等待 `/api/health` 中 `auto_detection.running=true`。
诊断API均在 `/api/debug/recordings` 下；起止和标记请求需要同源JSON，下载仅允许已登记的ID和文件名。
